# 智能救援小车：MaixCAM 视觉端

本项目运行在 MaixCAM／MaixCAM Pro，使用 YOLO 识别物块与场地，通过串口与 STM32 协作完成首次绿色物资、后续物资／伤员抓取、载荷清点和安全区定位。视觉端负责识别、筛选、目标关联、视觉事件；电机、夹爪、挡板及动作时间由 MCU 控制。

说明以当前代码为准。视觉与 MCU 协议互相依赖，**更新时需同步两端**；当前阈值是试用值，不代表已经完成实车标定。

| `serial_controller.py` | MCU 指令解析、视觉状态机、目标追踪和串口发送 |

## 模型和类别

当前 `app_config.py` 配置模型路径 `/root/sd/gongxun27/model_10439.mud`，须与设备的 SD 卡文件匹配。检测置信度默认为 0.5，黑色 0.7、安全区 0.4，IOU 0.45。按标签映射类别，不能把模型输出的原始索引直接当 UART ID。

| UART ID | 语义 | 标签 |
| --- | --- | --- |
| 1 / 2 | 蓝／红安全区 | `bluesafety` / `redsafety` |
| 3 | 浅蓝危险物资 | `sqareblue` |
| 4 | 红色伤员 | `sqarered` |
| 5 | 绿色普通物资 | `sqaregreen` / `sqareredgreen` |
| 6 | 黑色高分物资 | `triangualrblack` |

`blackbar`、`startzone` 是辅助检测，不作为物块 UART ID。实际模型标签以文件及 `model_class_mapping.py` 为准。

## 任务流程

1. MCU 选择类别并发 `03`，视觉寻找目标；进入条件后发 `04`，等待 MCU `04` 应答再按对应状态追踪。
2. `04` 满足条件发送 `14`；随后按目标和整理结果进入 `24` 或 `02/12/22`、`32/42` 等流程。各动作时序由 MCU 管理，需按方向理解握手。
3. `24` 跟踪抓取目标；达到捕获判据后发事件，由 MCU 完成夹爪动作。首次绿色、后续物资、伤员与补抓在清点／分流上存在区别，不能仅根据检测框判断已抓住。
4. MCU 发 `15/25` 选择安全区并进入 `05` 清点。等待近视角稳定后，视觉根据物块类别和数量决定整理、重新抓取或先报告载荷再发 `06`。
5. `06` 找对应颜色安全区，发现后发 `16` 并发送坐标。安全区足够大时还要判断黑杆；必要时发 `46` 等待避让完成，否则可发 `26` 请求推进。最终运动由 MCU 执行。
6. 07 后可以选择 `51` 黑／绿搜索和补抓；丢失由 `E3/E4/EE` 等机制处理。普通物资 E3 搜索期间可请求 `11` 切换伤员，需等待 MCU `11 → 03` 后使用新图像；实际补抓期间保留原任务规则。

`104/114/102` 等是视觉程序内部等待状态，不是串口单字节。上述为主线，事件的状态约束、超时、重复帧及补抓例外以代码为准。

## 串口协议

默认 `/dev/ttyS0`，115200 baud。接线、电平和接口映射应以实际设备为准。

```text
MCU → 视觉：E1 E2 CMD 1E 2E
视觉 → MCU：F1 F2 EVENT 1F 2F
视觉 → MCU：F1 F2 ID XH XL XS YH YL YS 1F 2F
```

X、Y 为大端两字节绝对值加符号（`01` 正、`02` 负），是相对**当前状态参考点**的像素误差；03、04、24 和安全区的参考点不一定相同。05 中零误差类别帧用于载荷报告，不是运动到位。图像、锁定及状态切换的旧帧不能作为新阶段坐标。

正式入口启用夹爪几何扩展：物块坐标 ID 高位携带同帧面积标志，低四位为类别。高位 `0x80` 表示含几何信息，`0x40` 表示达到近距离面积阈值，`0x20` 表示达到张爪面积阈值；安全区和载荷报告仍用普通 ID。符合最终捕获条件时视觉发送 `F1 F2 64 1F 2F`，新版 MCU 将其映射为内部 34 捕获事件；MCU 首块收纳确认仍为 `E1 E2 34 1E 2E`。不可将新视觉与旧 MCU 混用。

常用丢失事件：`E3` 搜索、`E4` 追踪、`EE` 24、`E5` 首次绿色清点恢复、`E6` 安全区；`13/F1/44` 等是对应恢复握手。具体接收范围与回复见 `serial_controller.py` 和 MCU 工程。当前 `AE` 出发区避让及 `36` 障碍检测默认关闭，保留代码不代表启用。

## 夹爪和安全区阈值

以检测框被图像边界裁剪后的可见面积除以整帧面积：

- 面积达到 **2%**：通过坐标标志通知 MCU 进入近距离谨慎追踪。
- 面积达到 **3%** 且目标中心相对抓取准星横向误差 **±15 像素以内**：满足张爪的面积和横向条件。后续捕获还需满足各类别原有 24 判据；伤员存在位置及连续帧要求。
- 安全区面积达到 **50%** 是 `26` 的条件之一，仍有确认帧、黑杆和握手约束，不能理解成单帧自动推进。

这些阈值位于 `app_config.py`，2% 和 3% 为当前试用值，受物块大小、视角、遮挡及刹车距离影响，需实车标定，不能直接当作实际距离。追踪摄像头舵机角度由 MCU 控制。

## 部署和调试

1. 在 MaixVision／设备使用兼容的 MaixPy 环境，确认模型 `.mud` 和引用文件、SD 卡路径、摄像头；应用打包清单为 `app.yaml`。
2. 核对串口及接线，确保 MCU 和视觉版本匹配；正常程序入口为 `main.py`。
3. 检查启动日志、命令收发和状态。默认不逐包打印坐标；需要诊断时可在 `app_config.py` 调整 `VISION_DIAGNOSTICS_VERBOSE`、`VISION_COORDINATE_LOG_ENABLED`。
4. 先架空车轮检查舵机、握手、丢失停车和清点，再低速实测。出现推偏时记录框面积、X/Y、目标 ID、两端状态及 MCU 输出，检查准星与机械夹爪是否实际对齐。

主机上可在项目目录运行 `python -B -m unittest discover`。测试模拟相机和串口，不能替代 MaixCAM 设备推理或实车验证；缺少依赖时先检查测试环境。
